# Hundo — Fase 3 (comunidad) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que la comunidad se vea y se use: votar reseñas como "útil" (con la insignia Top reviewer), seguir jugadores y ver su actividad, explorar rankings (global, por género, más reseñados), y llenar las páginas Reseñas y Jugadores y los juegos destacados de la portada.

**Architecture:**
- Two new tables, `review_likes` and `follows`. Each has RLS and column permissions, the same model as `ratings`.
- The counters (`ratings.helpful_count`, `profiles.helpful_received`) are kept up by a Postgres trigger, so the page only reads them.
- Rankings and lists that need aggregation (genres, genre rank, featured, players) are SQL functions called with `rpc()`.
- Public lists are read with the anonymous client inside `"use cache"` with `cacheLife("minutes")`.
- Anything that depends on the session (the like button, following, the feed) goes inside `<Suspense>`.

**Tech Stack:** igual que la Fase 2 (Next.js 16.4.6 + Cache Components, Supabase Postgres/RLS, next-intl, Tailwind v4, Motion 14.9.1, Vitest). `useOptimistic` de React 19 para los botones "Útil" y "Seguir".

**Spec:** `docs/2026-11-16-hundo-design.md` — §5.3 (reseñas y reputación), §5.4 (Inicio, Ficha: "puesto en su género", Seguir/feed, Explorar), §8 (modelo de datos: `review_likes`, `follows`), §11 punto 3.

## Global Constraints

Everything from the Global Constraints of Phases 1 and 2 still applies:
- zero cost;
- en/es with matching keys (the `src/lib/messages.test.ts` test);
- design tokens;
- secrets only in environment variables;
- the scale only via `getScaleCategory`;
- the definition of a valid vote and the trimmed mean.

**Reviews and reputation**
- **"Útil" (helpful):** one per user per review (PK `(user_id, rating_id)`).
  - You can't mark your own.
  - It applies only to ratings with a non-empty review that aren't hidden.
  - A suspended user can't vote.
- **Default review order:** most helpful (`helpful_count desc, updated_at desc`). The alternative is most recent (`updated_at desc`).
- **Top reviewer:** a user who has received **50 or more** "útil" in total (`profiles.helpful_received >= 50`). The constant is `TOP_REVIEWER_MIN = 50`.
- Professional critics get no special distinction: the badge depends only on likes.

**Following and feed**
- **Follows:** PK `(follower_id, followee_id)`; you can't follow yourself (`check (follower_id <> followee_id)`).
- **Feed:** ratings from the people you follow, `updated_at desc`, 20 per page, with cursor `?before=<ISO timestamp>`.

**Explore, rankings and featured**
- **Explore:** best rated globally and by genre (only games with `valid_ratings_count >= 5`), and most reviewed (`reviews_count desc`, `reviews_count > 0`).
- **Featured on the home page** (spec decision): the games rated most in the last 30 days (`ratings.created_at >= now() - interval '30 days'`, non-hidden ratings), computed automatically. Up to 6.
- **Position in its genre:** the game's rank inside its **first** genre (`genres[1]`), among games with a score. Ties share a position (`rank()`). Only shown if the game has a score.

**Pagination and conventions**
- Pagination (spec §12): cursor `?before=` for the feed; `?page=` (1-based, 20 per page) for the Reviews page; fixed lists of 20 in Explore and Players.
- User-search input is escaped before going into `ilike` (`%`, `_` and `\` are literals).
- Commits **without** the `Co-Authored-By` line (public repo, Gael's decision).
- Windows: `npx.cmd`/`npm.cmd`; Supabase CLI with `--remote` (dev) or `--remote=emrebckwpeuzcneeqkkn` (prod); `db query --yes` only for tests and authorized migrations.

**Out of scope (Phase 4):** Top 5 favorites, editing avatar/bio, importing Excel, reports and moderation, Google/Discord login, notifications.

## Review Focus

- **Duplicate likes or a like on your own review:** someone double-clicks "Útil" quickly, or tries to like their own review through the API. Expected: the counter goes up by 1, not 2, and liking your own review is rejected by the database. → SQL test in Task 1 + `useOptimistic` in Task 3.
- **The Top reviewer badge must follow likes both ways:** a reviewer with 50 likes loses one because its author removes it, or the review gets deleted. Expected: `helpful_received` goes down and the badge disappears at 49. → SQL test in Task 1.
- **Hostile player searches:** typing `%`, `_` or `\` doesn't return "everyone" and doesn't break the query. → unit test of `escapeLike` in Task 6.
- **Following and the feed in edge cases:** following yourself (rejected by the database); following someone suspended (they vanish from the feed because RLS hides them); and an empty feed (a message pointing to Players, not a blank page). → SQL test in Task 1 + render in Task 5.
- **Rankings with too little data:** a genre with no scored games, or a game without genres. Expected: an empty state with an explanation, no error, and the game page shows no rank. → SQL test in Task 2 + render in Task 7.
