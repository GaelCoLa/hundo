# Hundo — Fase 1 (base publicada) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dejar Hundo online en Vercel con el diseño aprobado, inglés/español, registro e inicio de sesión con email, y la base de datos de perfiles en Supabase.

**Architecture:** Next.js (App Router, TypeScript) servido por Vercel. Supabase aporta Postgres (con Row Level Security) y Auth. Los cambios de base de datos viven como migraciones SQL versionadas en `supabase/migrations/` y se aplican con la CLI de Supabase. La lógica de dominio pura (escala, validaciones) vive en `src/lib/` con pruebas Vitest.

**Tech Stack:** Next.js (última estable) + React + TypeScript, Tailwind CSS v4, next-intl, @supabase/supabase-js + @supabase/ssr, Supabase CLI (vía `npx`), Vitest, Vercel.

**Spec:** `docs/2026-11-16-hundo-design.md` (diseño visual: `docs/mockups/mix-approved.html`)

## Global Constraints

- Costo cero: solo planes gratuitos (Supabase Free, Vercel Hobby).
- Inglés por defecto, español disponible; rutas `/en/...` y `/es/...`. Ningún texto visible queda escrito directo en un componente: todo sale de `messages/en.json` / `messages/es.json`.
- Escala exacta: 1–39 Mediocre/Mediocre `#E5484D`; 40–59 Fair/Regular `#F2884B`; 60–74 Decent/Aceptable `#F5C451`; 75–84 Good/Bueno `#9BD35A`; 85–89 Great/Muy bueno `#46C27A`; 90–94 Excellent/Excelente `#3AA8E0`; 95–100 Masterpiece/Obra maestra `#B57CFF`.
- Tokens: fondo `#0F1424`, superficie `#182038`, borde `#2C3654`, texto `#EEF1F8`, texto secundario `#9AA3BD` y `#B9C0D4`, acento `#FFC94A`.
- Tipografías: Big Shoulders Display (titulares y números), Figtree (texto), Unbounded (solo logotipo), cargadas con `next/font/google`.
- Usuario: 3 a 20 caracteres `[a-z0-9_]`, único sin distinguir mayúsculas.
- Secretos solo en variables de entorno (`.env.local` local, panel de Vercel online). `.env*` en `.gitignore`. Nunca la `service_role` key en código de cliente.
- Docker no está instalado: no se usa Supabase local. Se usan dos proyectos Supabase gratuitos: `hundo-dev` (desarrollo y pruebas) y `hundo-prod` (la página online).
- Explicación para Gael: cada archivo que enseña algo (RLS, middleware, clientes de Supabase) lleva un comentario breve en español al principio diciendo qué hace y por qué.

## Review Focus

- Usuario con mayúsculas o espacios ("Gael CoLa"): debe rechazarse con un mensaje claro, no fallar en la base de datos. → prueba en Task 4.
- Dos personas eligen el mismo usuario con distinta capitalización ("gael" y "Gael"): la segunda recibe "Username taken". → índice único en minúsculas, Task 3; mensaje, Task 4.
- Notas en el borde exacto de cada rango (39/40, 59/60, 74/75, 84/85, 89/90, 94/95) y fuera de rango (0, 101, 92.5): la categoría correcta o un error. → Task 2.
- Una clave de traducción presente en inglés pero ausente en español (o al revés) muestra la clave cruda en pantalla. → prueba de paridad, Task 2.
- Visitante sin sesión en una página que la requiere (`/settings`): redirige al login y vuelve luego. → Task 4.

**Interfaces:**
- Consumes: middleware de next-intl de Task 2.
- Produces:
  - Tabla `public.profiles(id uuid PK references auth.users on delete cascade, username text not null, display_name text, avatar_url text, bio text check (char_length(bio) <= 300), locale text not null default 'en' check (locale in ('en','es')), is_admin boolean not null default false, is_suspended boolean not null default false, created_at timestamptz not null default now())`
  - Índice único `profiles_username_lower_idx on profiles (lower(username))`; `check (username ~ '^[a-z0-9_]{3,20}$')`
