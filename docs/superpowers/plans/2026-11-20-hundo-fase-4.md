# Hundo — Fase 4 (perfil editable, reportes y moderación) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que cada jugador pueda editar su perfil (avatar, nombre visible, bio, Top 5 favoritos) y borrar su cuenta, que cualquiera pueda reportar una reseña abusiva, y que Gael (administrador) pueda ocultar reseñas, suspender cuentas y cerrar reportes desde un panel.

**Architecture:** Avatares en Supabase Storage (bucket público `avatars`, una carpeta por usuario protegida por RLS de `storage.objects`); la base guarda solo la ruta del archivo. Favoritos en una tabla nueva `favorites`. Reportes en `reports`; las acciones de moderación son funciones SQL `security definer` que primero verifican `public.is_admin()`, así la regla "solo el admin" vive en la base. Borrar la cuenta usa el cliente con la clave secreta (`auth.admin.deleteUser`) y la cascada de claves foráneas borra todo lo demás (los triggers de contadores ya descuentan).

**Tech Stack:** lo de las fases 1–3 + Supabase Storage. Formularios con server actions y `useActionState`.

**Spec:** `docs/2026-11-16-hundo-design.md` — §5.4 (Perfil: avatar, bio, Top 5 favoritos; Reportar + panel de moderación; Configuración: editar perfil, borrar cuenta), §8 (`favorites`, `reports`, `profiles.is_admin/is_suspended`). Fuera de alcance por decisión de Gael (20/11/2026): importar Excel/CSV y login con Google/Discord.

## Global Constraints

- Todo lo de las fases 1–3 sigue vigente (costo cero, en/es con paridad, tokens, secretos solo en variables de entorno, commits sin `Co-Authored-By`, embeds `profiles!ratings_user_id_fkey`, triggers de `ratings` por columna).
- **Perfil** (límites que ya impone la base): `display_name` ≤ 40 caracteres, `bio` ≤ 300, ambos opcionales (vacío → NULL). El nombre de usuario NO se edita en esta fase.
- **Avatar:** PNG, JPEG o WebP, **máximo 2 MB**. Se guarda en `avatars/<user_id>/<timestamp>.<ext>`; `profiles.avatar_url` guarda solo esa ruta. La URL pública se arma en el servidor y solo si la ruta tiene la forma `^[0-9a-f-]{36}/\d+\.(png|jpg|webp)$` (así nadie puede apuntar su avatar a otro sitio). Al subir uno nuevo se borra el anterior. `serverActions.bodySizeLimit: "3mb"`.
- **Top 5 favoritos** (spec §8: `favorites (user_id, position 1..5) PK, game_id`): solo juegos que el usuario calificó; sin repetidos; el orden elegido es el que se muestra.
- **Borrar cuenta:** hay que escribir el propio nombre de usuario para confirmar; borra la cuenta de Auth (y en cascada perfil, calificaciones, likes, seguimientos, favoritos, reportes propios) y los archivos de avatar; cierra la sesión.
- **Reportes:** una reseña ajena, visible y con texto; un reporte por persona y reseña (`unique (reporter_id, rating_id)`); motivo `spam | offensive | spoilers | other`, detalle opcional ≤ 500. Un suspendido no reporta.
- **Moderación** (solo `is_admin`): ocultar/mostrar una reseña (`ratings.is_hidden`), suspender/reactivar una cuenta (`profiles.is_suspended`, y recalcular la nota de los juegos que calificó: sus votos dejan de ser válidos), cerrar un reporte. Spec §5.4: un suspendido puede iniciar sesión y leer, pero no calificar, reseñar, votar ni seguir; su perfil y sus reseñas dejan de ser públicos (ya lo cumplen las RLS existentes).
- **Panel** `/admin`: 404 para quien no es admin (no revelar que existe).

## Review Focus

- Un usuario sube como avatar un archivo de 50 MB, un `.svg` con script o un `.exe` renombrado a `.png` → se rechaza con mensaje claro, sin guardar nada. → prueba de `validateAvatar` (Task 3) + límites del bucket (Task 1).
- Un usuario intenta subir/borrar archivos en la carpeta de otro usuario, o escribir `avatar_url` apuntando a otro dominio → Storage lo rechaza / el sitio no lo muestra. → prueba SQL de políticas de Storage (Task 1) + prueba de `avatarPublicUrl` (Task 3).
- Un usuario común llama directo a `moderate_rating` / `set_suspended` / `resolve_report` desde la API, o lee todos los reportes → `forbidden` / solo ve los suyos. → prueba SQL (Task 2).
- Favoritos con un juego repetido, 6 juegos, o un juego que no calificó → error claro. → prueba de `validateFavorites` (Task 4) + check en la base (Task 1).
- Borrar la cuenta escribiendo mal el usuario → no borra nada; borrar una cuenta con likes recibidos/dados → los contadores de los demás quedan bien. → prueba de `confirmMatches` (Task 5) + prueba SQL de cascada (Task 2).

### Task 2: Base de datos — reportes y moderación

**Files:**
- Create: `supabase/migrations/20261122000002_moderation.sql`, `supabase/tests/moderation.sql`

**Interfaces:**
- Produces:
  - `reports(id uuid pk default gen_random_uuid(), reporter_id uuid → profiles on delete cascade, rating_id uuid → ratings on delete cascade, reason text check in ('spam','offensive','spoilers','other'), details text check (char_length(details) <= 500), status text not null default 'open' check in ('open','resolved'), created_at, resolved_at timestamptz, unique (reporter_id, rating_id))`.   - Funciones `security definer`, cada una empieza con `if not public.is_admin() then raise exception 'forbidden'; end if;`:
    - `public.moderate_rating(p_rating_id uuid, p_hidden boolean) returns void` — pone `is_hidden` (el trigger de `ratings` por columna recalcula el juego) y cierra los reportes abiertos de esa reseña.
    - `public.set_suspended(p_user_id uuid, p_suspended boolean) returns void` — actualiza `profiles.is_suspended` y llama `refresh_game_stats` por cada juego que calificó ese usuario.
    - `public.resolve_report(p_report_id uuid) returns void` — `status = 'resolved'`, `resolved_at = now()`.
    - `public.open_reports() returns table(report_id uuid, rating_id uuid, reason text, details text, created_at timestamptz, reporter text, author text, author_id uuid, author_suspended boolean, review text, is_hidden boolean, score smallint, game_slug text, game_name text, reports_on_rating int)` — reportes abiertos, más viejos primero (ve reseñas ocultas y autores suspendidos, por eso es `security definer`).
  - `grant execute` de las cinco a authenticated; `revoke` de public/anon.
